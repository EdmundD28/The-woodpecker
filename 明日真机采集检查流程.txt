木材敲击项目——ESP32固件A真机采集检查流程
==========================================

适用硬件：ESP32-WROOM-32D、DFR0052压电振动传感器
固件工程：firmware_a_sample
电脑工具：pc_collector/collector.py
数据协议：WOOD_IMPACT_V1


一、测试目标
------------

本次真机测试需要确认：

[ ] ESP32能够读取真实压电敲击信号。
[ ] 能以16000 Hz、1024点固定窗口完成一次采样。
[ ] 能保存触发前256点和触发部分768点。
[ ] 软件触发能够工作。
[ ] 真实敲击阈值触发能够工作。
[ ] ESP32能够通过串口输出完整JSON。
[ ] collector能够读取、验证并保存JSONL。
[ ] collector能够保存并显示Matplotlib波形。
[ ] 正常敲击没有严重削顶或频繁丢样。
[ ] 得到可以交给罗的真实示例文件。


二、需要准备的物品
------------------

[ ] ESP32开发板。
[ ] 支持数据传输的USB线。
[ ] DFR0052压电振动传感器。
[ ] 经电路负责人确认的保护/限压电路。

三、通电前检查
--------------

第一步：确认DFR0052接口。

正确连接关系：

DFR0052 GND    -> ESP32 GND
DFR0052 NC     -> 不连接
DFR0052 Analog -> 保护/限压电路 -> ESP32 GPIO34

逐项确认：

[ ] ESP32尚未通过USB供电时再进行接线。
[ ] DFR0052的GND与ESP32的GND相连。
[ ] NC引脚悬空，没有连接3.3V或5V。
[ ] Analog最终连接GPIO34。
[ ] GPIO34没有直接连接5V。
[ ] 接线牢固，没有短路或松动。
[ ] 压电片、木头和线缆已经固定。

第二步：确认保护电路。

DFR0052内部约有1 MΩ泄放电阻和5.1 V钳位，但ESP32 ADC属于3.3 V系统，
因此仍需由电路负责人确认GPIO34前的保护方案。

[ ] 确认最大正向电压不会超过ESP32允许范围。
[ ] 确认负向脉冲不会直接进入GPIO34。
[ ] 确认有限流、分压或适合3.3 V ADC的钳位措施。
[ ] 如果有示波器，先在Analog尚未连接GPIO34时测量输出峰值。

注意：轻敲不能代替保护电路。即使轻敲，压电片也可能产生很短的电压尖峰。

十、根据结果调整触发阈值
------------------------

当前初始值：

TRIGGER_THRESHOLD = 200

判断方法：

1. 如果静止时不断自动触发：提高阈值。
2. 如果正常敲击也无法触发：降低阈值。
3. 如果碰线就触发：固定线缆并检查接地和噪声。
4. 阈值应高于静止最大噪声偏差，并低于最轻有效敲击偏差。

理想关系：

静止最大噪声偏差 < 触发阈值 < 最轻有效敲击偏差

每次修改TRIGGER_THRESHOLD后，需要重新Build并Upload固件A。

十一、采集三个位置
------------------

位置1单次：

py .\collector.py --port COM7 --impact-point 1 --trigger auto --count 1 --show

位置2单次：

py .\collector.py --port COM7 --impact-point 2 --trigger auto --count 1 --show

位置3单次：

py .\collector.py --port COM7 --impact-point 3 --trigger auto --count 1 --show

批量采集时，例如每个位置5次：

py .\collector.py --port COM7 --impact-point 1 --trigger auto --count 5
py .\collector.py --port COM7 --impact-point 2 --trigger auto --count 5
py .\collector.py --port COM7 --impact-point 3 --trigger auto --count 5

批量采集时可以省略--show。PNG仍会保存，但不会每次弹窗阻塞流程。

如果希望同一个波形窗口在每次敲击完成后立即刷新，使用：

py .\collector.py --port COM7 --impact-point 1 --trigger auto --count 5 --live

--live模式会在每收到一条完整的1024点记录后刷新曲线；它不是采样过程中的逐点滚动显示。
采集结束后最后一条波形会保持显示，关闭图窗即可结束。

如果希望持续观察压电片变化，同时保留完整敲击采集，使用：

py .\collector.py --port COM7 --impact-point 1 --trigger auto --monitor

--monitor窗口上半图持续滚动显示最近5秒的250 Hz峰值预览；每个预览点取对应64个原始点中偏离基线最大的点，下半图显示最近一次完整的16 kHz、1024点波形。关闭窗口或按Ctrl+C才停止监测。
预览数据不写入训练JSONL，完整敲击数据仍按WOOD_IMPACT_V1保存。

[ ] P01数据的impact_point_id为1。
[ ] P02数据的impact_point_id为2。
[ ] P03数据的impact_point_id为3。
[ ] 同一位置的strike_id能够递增。
[ ] 每次敲击间隔至少一秒。

十三、常见故障排查
------------------

1. 找不到COM端口

- 检查USB线是否支持数据传输。
- 更换USB接口。
- 检查CH340或CP210x驱动。

2. 无法打开串口

- 确认COM编号正确。
- 关闭Serial Monitor。
- 关闭另一个collector或串口软件。

3. 等待60秒超时

- 确认板子上是最新版固件A。
- 检查Analog是否接到GPIO34。
- 检查压电片是否固定和正常。
- 检查阈值是否过高。

4. 输出乱码或JSON解析失败

- 确认固件、collector和Serial Monitor均为115200。
- 检查串口数据是否被其他调试文字污染。

5. 出现CLIPPED

- 检查保护、分压、偏置和ADC量程。
- 不要只通过提高触发阈值解决削顶。

6. 频繁出现SAMPLE_LOSS

- 重复测试排除偶发现象。
- 如果持续发生，需要改用ESP32连续ADC或硬件定时采样。

7. 静止时不断触发

- 提高阈值。
- 固定线缆。
- 检查GPIO浮空、接地和电路噪声。
