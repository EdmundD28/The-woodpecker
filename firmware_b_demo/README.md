# 固件 B：逐点质量检查与三点联合识别

本目录为 `main` 分支的展示固件交付。历史集成工程为 `The-woodpecker-model/firmware_b_demo`。
本次编译、数值对照与未验证项目见[VERIFICATION.md](VERIFICATION.md)。固件已生成，尚未烧录。
沿用原采集工程分支`wood-impact-system-wjy`（7401b8c）的触摸、OLED、ADC及三点识别实现，再加入只学习正常分布的单击质量模型。本次按目录整理到 `main`，未合并固件 A 的源码改动。

每个点采完先做统一质量检查；不合格保留当前点和此前合格数据，松开再按住后只重测当前点；三个点都合格才联合判断木头1或木头2。支持端点—中点—另一端点的123/321，开机默认时域识别与场地容错质量档。

## 换场地与质量档位

- **默认场地容错档（VENUE）**：使用25个形态特征，不把绝对峰峰值和均方根大小用于最近正常参考距离，减少力度与耦合幅值变化的影响。端点/中点各自仅用58条正常校准集中的对应记录重新确定基础阈值，再明确放宽为1.5倍。
- **严格档（STRICT）**：原27个特征和原始阈值，仍包含绝对幅值，主要用于复核。
- 两档都严格检查丢样、削顶和峰峰值小于100的弱信号；不会绕过这些基础检查。
- 串口115200发送`V`选择容错档，`S`选择严格档。采样中的约0.3秒和最终结果页不允许改档；其他时候只影响后续敲击，保留此前合格点。档位只在内存中保存，重新上电恢复VENUE。
- 每点连续三次形态拒收显示`CHECK / contact/noise / retry here`，保留当前点，提示检查接触、外界振动和噪声。**不会自动越放越松，不会从拒收波形在线学习**。没有足够的新场地正常数据时，不自动做“现场校准”。
- 阈值和分数通过`#QUALITY`输出；`?`查询当前点、档位和重测次数。

当前300条离线对照：两档均拦下5/5指定异常，61条假定正常测试均未被误拦。默认档针对换场地的模拟扰动检查：

| 扰动（非新场地实测） | 原严格档要求重测 | 默认容错档要求重测 |
|---|---:|---:|
| 原始61条 | 0/61 | 0/61 |
| 基线整体增加或减少150 ADC单位 | 0/61 | 0/61 |
| 振幅降至70% | 59/61 | 0/61 |
| 振幅增至130% | 54/61 | 0/61 |
| 添加标准差30 ADC单位的随机噪声 | 7/61 | 0/61 |
| 振幅70%并添加标准差30的噪声 | 61/61 | 0/61 |
| 添加标准差80 ADC单位的随机噪声 | 60/61 | 35/61 |

**容错不是任意环境保证**：噪声很大、装夹共振或传感器位置改变时仍可能频繁拒收；质量通过也不保证木头识别在新环境一定正确。默认档是在观察模拟敏感性后制定的部署策略，以上是开发诊断，不是全新未参与开发的验收集。新的正常数据和误采类型仍需现场采集验证。

质量模型只使用原176条正常训练参考及58条正常校准数据。5条指定异常没有参与参考拟合或阈值校准；模型文件来源、阈值和校验值见`include/models/quality_deployment.json`。

## 现在烧录哪一版

默认`esp32dev`采用逐击均方根归一化＋对数压缩频谱网络，模型`REAL-RMSLOG-fb6b2bf9d8ef`，12114参数。`esp32dev_spectrum`是相同模型的显式别名；`esp32dev_time`保留原时域模型`REAL-TRIPLET-beecd884647a`。

采用版在桌面与地毯共同训练，排除原5条指定异常，174/56/65条原始敲击分为训练/验证/开发留出，全部归一化和对数尺度只拟合训练池。630个留出组合和16个不复用组三点均判对，但记录此前已用于开发，不是新增现场验收。

此前六源划分迁移对照中，归一化＋对数频谱网络平均为地毯→桌面93.10%、桌面→地毯99.81%；这不能直接作为当前共同训练权重在陌生场地的成绩。详见[模型说明](include/models/README.md)。

本次没有烧录开发板。现有质量检查、触摸、采样与600触发阈值保留。

## 烧录和操作

1. 连接 ESP32，关闭占用串口的采集程序和串口监视器。
2. VS Code 打开本工程，选择 `esp32dev` 的 `Upload`；默认端口 COM7。也可在本目录运行 `./flash_rehearsal.ps1`，端口不同时加 `-Port COM实际编号`。
3. 开机播放啄木鸟开屏动画。先松开 GPIO27 的触摸开关，再按住约 1 秒，等屏幕显示 `TAP!` 后敲击；保持按住直到显示 `NICE!`。未触摸时敲击不会采样。
4. 一次按住最多采集一次，采集成功或被拒都须松开再按住。依次敲 **端点 → 中间点 → 另一个端点**，每点重新按住、等 `TAP!`。沿用训练时相同三个位置和装夹状态，支持 123 或 321。
5. 每次先质量判定，通过后才保存。前两次不分类，第三次通过后联合判断；屏幕显示 `WOOD 1`或`WOOD 2`，对应木头编号，不能解释为实心/空心或缺陷诊断。结果一直保留，重新按住 1 秒后先播放补洞动画，再开始新组。
6. 采集中松开触摸会显示 `let go early`，当前点作废，保留此前合格点。被拒时显示原因：`too hard!`（CLIPPED）、`too soft`（WEAK_SIGNAL）、`missed it`（SAMPLE_LOSS）、`odd tap / retry here`（SHAPE_OUTLIER）、`can't check`（QUALITY_ERROR）或`can't read it`（PREPROCESS_ERROR）。串口`#INVALID`给出代码；松开、重新按住后重敲当前点。敲错位置或换木头时，在串口发送`R`清空整组；采集中不接受重置。

默认即新频谱模型；`-Spectrum`显式选择相同模型。需要旧时域对照时，选择`esp32dev_time`或运行`./flash_rehearsal.ps1 -Time`。串口`#INIT`显示实际识别模型。不要同时上传两个环境，后上传的会替换前一个。

串口 115200；`C` 仅在按住并显示 `TAP!` 时软件触发真实 ADC 窗口，不能绕过触摸许可，静止信号通常被拒为弱信号。`#INIT` 显示模型版本和采样设置，`#TOUCH` 显示许可状态及 GPIO 电平，`#RESULT` 给出木头编号、两个模型分数和推理耗时 `infer_ms`。分数未经概率校准，未设置经过验证的低置信度阈值，也没有据此伪造“不确定”判定。

## 接线和采样

- OLED SSD1306 128×64：VCC→3V3、GND→GND、SDA→21、SCL/SCK→22，地址 0x3C。
- 压电经现有保护和偏置电路接 GPIO34，ADC1 通道 6。
- 三针触摸开关：VCC→3V3、GND→公共地、I/O→GPIO27。使用外部数字输出，不是 ESP32 内置触摸测量。默认触摸输出高电平、内部下拉；低电平有效模块在 `main.cpp` 将 `TOUCH_ACTIVE_LEVEL` 改成 `LOW`，会自动改为上拉。模块须保持触摸有效、松开立即复位，不能使用触摸一次切换开关状态的自锁模式。实物有效电平尚未确认。
- 8 kHz、2400 点（300 ms）、触发前 256 点、12 位 ADC；演示试机的触发阈值改为 600 ADC 单位（训练数据采集时为 500）。质量检查默认使用场地容错档（VENUE）。
- 采集中不刷新 OLED；处理和结果显示时暂停 ADC。恢复时清旧 DMA，等待 500 ms 并补齐前缓存。显示 `TAP!` 后从容再敲。
- 触摸控制对应 A 版空格键的一次按住会话：开机先见到松开、按住 1 秒、一次按住最多一次尝试、采集中松开即取消；重新按住时丢弃旧缓存，屏幕刷新后重填 256 点前缓存。ADC 在锁定时继续运行以跟踪基线，只有触摸许可满足后才允许生成记录。不需要电脑心跳。
- 捕获超时设为 600 ms，覆盖触发后约 268 ms 的采样时间。模型工作缓冲区申请失败会输出 `#FATAL` 并停止。
- 屏幕画面和动画在 `include/oled_ui.h`、`include/oled_anim.h`，图案在 `woodpecker_art.h`、`fly_art.h`，字体在 `include/fonts/`（Source Serif 4，SIL OFL 1.1；TomThumb，BSD）。动画会阻塞，只在 ADC 暂停时播放。
- 屏幕冷启动：先等待 500 ms，以 400 kHz 通信；每轮最多尝试 6 次，每次间隔 500 ms。设备响应后间隔 150 ms 重发完整初始化，再检查总线；整轮失败则输出 `#OLED_WAIT`，等待 1 秒后继续重试，屏幕未就绪时不启动 ADC。开机标记为 `#BOOT,firmware=B_TOUCH_OLED_RETRY_V3_RUN_PIN25`。总线应答只能证明设备响应，不能证明像素已点亮。

## 模型接口和内存

三路输入顺序为端点、中间点、另一端点。每条波形独立减整个窗口均值，再除以 2048，不做峰值归一化。三路按采样点交错排列。正反两个方向各推理一次，平均 softmax 分数，保证交换两端结果一致。

新频谱版与训练一致：减均值并除以2048后，逐击做均方根归一化，再加对称Hann窗，计算2400点幅值谱除以2400，保留直流和奈奎斯特共1201频点；最后使用训练池拟合尺度做log1p压缩。两个端点共享参数，中点独立拟合。部署使用精确长度的混合基快速傅里叶变换，没有补零改成 4096 点。原导出头文件保留参考实现，实际推理由 `include/wood_classifier.h` 包装。

模型工作缓冲区在开机时一次申请，时域 76800 字节、频域 38656 字节；运行时不反复分配。输入两端原地交换后恢复，省去第二份输入缓冲区。频域另外静态保留变换缓冲和旋转因子。编译器报告的静态内存不包含这些开机申请、DMA、OLED 和运行栈，不能据此声称峰值内存或真机稳定性已验证。

质量检查在ADC暂停后、存储当前点之前执行，借用CNN工作缓冲中的34304字节做精确2144点的触发后频谱计算；不改写已存的三点输入。质量判定返回后才调用识别预处理或推理，两者没有并发访问。正常参考与变换常数保存在Flash，不额外申请质量FFT缓冲。质量计算耗时在`#QUALITY,quality_ms=`输出，ESP32实际耗时和栈余量仍需真机测量。

新频谱权重来自`20261019_adopted_rms_log_v1/spectrum`，旧时域仍来自`20261017_three_point_wood_id/time`。来源、LF头文件散列及预处理版本见`include/models/manifest.json`；可直接读取的Python模型见`include/models/spectrum_model.json`。

## 已验证与待验证

`./run_host_tests.ps1` 运行实际 `src/main.cpp`，只模拟 Arduino、OLED 和 DMA 接口。测试脚本默认读取本仓库 `test/fixtures` 保存的每模型6组三点原始波形及对应输入、分数；新频谱沿用此前已公开的原始输入，并按新模型重算输入和分数，同时核对时域与频域全部输入数值、预测分数、正反顺序、三次敲击流程、拒收重测、超时、整组重置、计时回绕。可用 `-Compiler` 指定本机 C++ 编译器，`-Run` 指定其他识别模型测试目录。报告保存在 `.host_tests/verification.json`。

两版已通过 ESP32 编译及上述离线验证，包括 GPIO27 开机按住锁定、按住 1 秒、一次一采、松开取消、重按清旧缓存和软件触发不可绕过许可。上一版已在真机读到初始化和 Ready，用户确认 OLED 已显示；本次触摸版本尚未烧录验证，实物触摸电平、采样率、推理延迟、运行内存和现场连续三击仍待实测。彩排先检查未按不采、按住可采、持续按住不重复、松开中途作废，再对两根木头分别完整敲一组。

冷启动重试另通过模拟测试：前几次设备未响应、全部失败后下一轮恢复、初始化失败、初始化后总线不再响应。实物出现烧录后或电池冷启动黑屏、手动复位后恢复，尚未确定根因；用户确认稳压 5V 接 VIN。本次修复必须在重新烧录后拔除 USB、完全断电再用电池启动验证，不能用串口自动复位替代冷启动验收。

质量实现见`include/signal_quality.h`，数据由`luo_analysis/export_quality.py`导出。`test/verify_quality.py`对全部300条原始记录逐项比较Python与C++特征、异常分数及两档重测决定；`test/venue_sensitivity.py`复现上面的扰动诊断。当前5条异常在两档均被拦截，但不能保证发现所有未来误采。

启动诊断版新增 `#BOOT_STAGE` 与 `#HEAP`：分别记录 OLED、模型内存申请、ADC 驱动安装与启动；进入主循环后发送 `?` 可查看 `#STATUS`。这是定位工具，不代表冷启动故障已解决。用户报告显示 Initialising 后接回 USB 即恢复，尚未获得电池供电时的故障日志。

独立运行指示：GPIO25 临时作为诊断输出，不接其他器件。仅主循环运行时每 1 秒翻转高低电平，万用表对 GND 测量约 0V 与 3.3V 交替；初始化阶段保持低。先在 USB 供电下确认该变化，再完全断电、只用电池启动比较。反复变化说明主循环在继续运行；不变化仅说明尚未观测到循环进展，不能单独证明芯片未启动。该诊断不依赖 OLED。
