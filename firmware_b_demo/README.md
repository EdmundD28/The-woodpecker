# 固件 B：三点联合 CNN 彩排版

已接入 2026-10-17 训练的时域和频域模型，替换原先按振幅分档、三次多数表决的占位流程。固件 A 未修改。工程路径为 `The-woodpecker/firmware_b_demo`，不要烧录旁边 `The-woodpecker-model` 中的旧 B 工程。

## 现在烧录哪一版

默认 `esp32dev`：时域 CNN，模型 `REAL-TRIPLET-beecd884647a`。
可选 `esp32dev_spectrum`：频域 CNN，模型 `REAL-TRIPLET-f392163987d7`。

| 模型 | 参数量 | 验证组合准确率 | 留出组合准确率 | 不复用波形测试 |
|---|---:|---:|---:|---:|
| 时域（彩排默认） | 2514 | 99.45% | 98.50% | 20/20 |
| 频域 | 12114 | 100.00% | 95.00% | 19/20 |

原训练按验证集预先选中了频域；这里看到留出结果后，选择时域作为彩排默认，是部署决策，不能算新的无偏选型验证。2000 个测试组合由 60 条留出敲击组合而成，并非 2000 次独立实测。两版都只识别当前两根木头，不是木材品种或缺陷识别器。

## 烧录和操作

1. 连接 ESP32，关闭占用串口的采集程序和串口监视器。
2. VS Code 打开本工程，选择 `esp32dev` 的 `Upload`；默认端口 COM7。也可在本目录运行 `./flash_rehearsal.ps1`，端口不同时加 `-Port COM实际编号`。
3. 开机播放啄木鸟开屏动画，右下角显示 `TIME`。先松开 GPIO27 的触摸开关，再按住约 1 秒，等屏幕显示 `TAP!` 后敲击；保持按住直到显示 `NICE!`。未触摸时敲击不会采样。
4. 一次按住最多采集一次，采集成功或被拒都须松开再按住。依次敲 **端点 → 中间点 → 另一个端点**，每点重新按住、等 `TAP!`。沿用训练时相同三个位置和装夹状态，支持 123 或 321。
5. 前两次只保存数据，第三次联合判断。屏幕显示 `SOLID`（实心，质量正常）或 `HOLLOW`（空心，有质量隐患），类别编号只在串口 `#RESULT,wood=` 输出。结果一直保留，重新按住 1 秒后先播放补洞动画，再开始新组。
6. 采集中松开触摸会显示 `let go early`，当前点作废，保留此前合格点。被拒时屏幕显示原因：`too hard!`（CLIPPED）、`too soft`（WEAK_SIGNAL）、`missed it`（SAMPLE_LOSS）、`can't read it`（PREPROCESS_ERROR），串口 `#INVALID` 仍给出原始代码。这些情况也停留当前点，松开、重新按住后重敲。敲错位置或换木头时，在串口发送 `R` 清空整组；采集中的约 0.3 秒不接受重置。

需要频域时，选择 `esp32dev_spectrum` 的 `Upload`，或运行 `./flash_rehearsal.ps1 -Spectrum`。开屏右下角显示 `SPECTRUM`。不要同时上传两个环境，后上传的会替换前一个。

串口 115200；`C` 仅在按住并显示 `TAP!` 时软件触发真实 ADC 窗口，不能绕过触摸许可，静止信号通常被拒为弱信号。`#INIT` 显示模型版本和采样设置，`#TOUCH` 显示许可状态及 GPIO 电平，`#RESULT` 给出木头编号、两个模型分数和推理耗时 `infer_ms`。分数未经概率校准，未设置经过验证的低置信度阈值，也没有据此伪造“不确定”判定。

## 接线和采样

- OLED SSD1306 128×64：VCC→3V3、GND→GND、SDA→21、SCL/SCK→22，地址 0x3C。
- 压电经现有保护和偏置电路接 GPIO34，ADC1 通道 6。
- 三针触摸开关：VCC→3V3、GND→公共地、I/O→GPIO27。使用外部数字输出，不是 ESP32 内置触摸测量。默认触摸输出高电平、内部下拉；低电平有效模块在 `main.cpp` 将 `TOUCH_ACTIVE_LEVEL` 改成 `LOW`，会自动改为上拉。模块须保持触摸有效、松开立即复位，不能使用触摸一次切换开关状态的自锁模式。实物有效电平尚未确认。
- 与采集这批训练数据的 A 版一致：8 kHz、2400 点（300 ms）、触发前 256 点、触发阈值 500 ADC 单位、12 位 ADC。
- 采集中不刷新 OLED；处理和结果显示时暂停 ADC。恢复时清旧 DMA，等待 500 ms 并补齐前缓存。显示 `TAP!` 后从容再敲。
- 触摸控制对应 A 版空格键的一次按住会话：开机先见到松开、按住 1 秒、一次按住最多一次尝试、采集中松开即取消；重新按住时丢弃旧缓存，屏幕刷新后重填 256 点前缓存。ADC 在锁定时继续运行以跟踪基线，只有触摸许可满足后才允许生成记录。不需要电脑心跳。
- 捕获超时设为 600 ms，覆盖触发后约 268 ms 的采样时间。模型工作缓冲区申请失败会输出 `#FATAL` 并停止。
- 屏幕画面和动画在 `include/oled_ui.h`、`include/oled_anim.h`，图案在 `woodpecker_art.h`、`fly_art.h`，字体在 `include/fonts/`（Source Serif 4，SIL OFL 1.1；TomThumb，BSD）。动画会阻塞，只在 ADC 暂停时播放。
- 屏幕冷启动：先等待 500 ms，以 400 kHz 通信；每轮最多尝试 6 次，每次间隔 500 ms。设备响应后间隔 150 ms 重发完整初始化，再检查总线；整轮失败则输出 `#OLED_WAIT`，等待 1 秒后继续重试，屏幕未就绪时不启动 ADC。开机标记为 `#BOOT,firmware=B_TOUCH_OLED_RETRY_V3_RUN_PIN25`。总线应答只能证明设备响应，不能证明像素已点亮。

## 模型接口和内存

三路输入顺序为端点、中间点、另一端点。每条波形独立减整个窗口均值，再除以 2048，不做峰值归一化。三路按采样点交错排列。正反两个方向各推理一次，平均 softmax 分数，保证交换两端结果一致。

频域版与训练一致：对称 Hann 窗、2400 点实信号傅里叶幅值、除以 2400、保留直流和奈奎斯特，共 1201 个频点。部署使用精确长度的混合基快速傅里叶变换，没有补零改成 4096 点。原导出头文件保留参考实现，实际推理由 `include/wood_classifier.h` 包装。

模型工作缓冲区在开机时一次申请，时域 76800 字节、频域 38656 字节；运行时不反复分配。输入两端原地交换后恢复，省去第二份输入缓冲区。频域另外静态保留变换缓冲和旋转因子。编译器报告的静态内存不包含这些开机申请、DMA、OLED 和运行栈，不能据此声称峰值内存或真机稳定性已验证。

权重直接复制自 `The-woodpecker-model/luo_analysis/runs/20261017_three_point_wood_id/{time,spectrum}/model_weights.h`，没有重新训练或删除异常样本；原始版本与校验值记录在 `include/models/manifest.json`。

## 已验证与待验证

`./run_host_tests.ps1` 运行实际 `src/main.cpp`，只模拟 Arduino、OLED 和 DMA 接口。测试脚本使用相邻模型工程保存的全部 6 组三点原始波形及训练导出的输入、分数，同时核对时域与频域全部输入数值、预测分数、正反顺序、三次敲击流程、拒收重测、超时、整组重置、计时回绕。可用 `-Compiler` 指定本机 C++ 编译器，`-Run` 指定训练结果目录。报告保存在 `.host_tests/verification.json`。

两版已通过 ESP32 编译及上述离线验证，包括 GPIO27 开机按住锁定、按住 1 秒、一次一采、松开取消、重按清旧缓存和软件触发不可绕过许可。上一版已在真机读到初始化和 Ready，用户确认 OLED 已显示；本次触摸版本尚未烧录验证，实物触摸电平、采样率、推理延迟、运行内存和现场连续三击仍待实测。彩排先检查未按不采、按住可采、持续按住不重复、松开中途作废，再对两根木头分别完整敲一组。

冷启动重试另通过模拟测试：前几次设备未响应、全部失败后下一轮恢复、初始化失败、初始化后总线不再响应。实物出现烧录后或电池冷启动黑屏、手动复位后恢复，尚未确定根因；用户确认稳压 5V 接 VIN。本次修复必须在重新烧录后拔除 USB、完全断电再用电池启动验证，不能用串口自动复位替代冷启动验收。

质量检查仍只覆盖丢样、削顶、明显弱信号；没有学习正常分布的质量检测器，**不能保证拦截 H038 等形态异常**。一次异常可能影响最终编号，模型判对也不代表波形合格。

启动诊断版新增 `#BOOT_STAGE` 与 `#HEAP`：分别记录 OLED、模型内存申请、ADC 驱动安装与启动；进入主循环后发送 `?` 可查看 `#STATUS`。这是定位工具，不代表冷启动故障已解决。用户报告显示 Initialising 后接回 USB 即恢复，尚未获得电池供电时的故障日志。

独立运行指示：GPIO25 临时作为诊断输出，不接其他器件。仅主循环运行时每 1 秒翻转高低电平，万用表对 GND 测量约 0V 与 3.3V 交替；初始化阶段保持低。先在 USB 供电下确认该变化，再完全断电、只用电池启动比较。反复变化说明主循环在继续运行；不变化仅说明尚未观测到循环进展，不能单独证明芯片未启动。该诊断不依赖 OLED。
